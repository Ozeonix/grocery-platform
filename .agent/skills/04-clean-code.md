# Skill — Clean Code

Write code that a new engineer can understand.

Prefer:
- small functions
- explicit names
- cohesive classes/modules
- dependency inversion where useful
- clear boundaries
- limited nesting

Avoid:
- premature abstractions
- generic helper dumping grounds
- giant classes
- giant controllers
- magic values
- duplicated logic
- dead code
- commented-out code
- clever code that saves a few lines but increases cognitive load
